TITLE
A `release` binding on its own key also fires after a key combo (Super+Return, Super + click)

BODY
**Version:** pleamar-wm 0.6.9 (`main` at 42c8fee), on pleamar 0.7.10. Seen in the session and reproduced in `pleamar-wm headless`.

**What I wanted:** the Windows key on its own, tapped and let go, opens a launcher (as on Windows and GNOME), while
Super+Return, Super+Q and Super with a drag keep doing what they do:

```
bind super_l release launch my-launcher
bind Super+Return launch kitty
```

**What happens:** the launcher also opens after Super+Return, and after Super with a click or a drag on a window,
as soon as Super is let go. `route.rs` decides what letting a key go will do when the key goes down (line 271,
`let later = keys.on_release(...)`) and runs it when it comes up (line 296, `self.bound.remove(k)`), whatever else
was pressed while it was held.

**Reproduce (headless):**

```sh
cat > /tmp/pwm/keys.conf <<'K'
bind super_l release launch sh -c 'echo fired >> /tmp/pwm/tap'
bind Super+Return launch true
K
# 1. Super held, Return, Super let go: expected nothing, gets "fired"
PLEAMAR_CONFIG=/tmp/pwm PLEAMAR_HEADLESS_INPUT="keydown:Super_L:125@1500 key:Super+Return:28@1800 keyup:Super_L:125@2200" \
  pleamar-wm headless --seconds 3.5
# 2. Super held, a click, Super let go: expected nothing, gets "fired"
PLEAMAR_CONFIG=/tmp/pwm PLEAMAR_HEADLESS_INPUT="keydown:Super_L:125@1500 900,400@1600 down@1800 up@1900 keyup:Super_L:125@2200" \
  pleamar-wm headless --seconds 3.5
# 3. Super alone: expected "fired", gets it
PLEAMAR_CONFIG=/tmp/pwm PLEAMAR_HEADLESS_INPUT="key:Super_L:125@1800" pleamar-wm headless --seconds 3.5
```

(`rm /tmp/pwm/tap` between runs.) Results, one line in `/tmp/pwm/tap` meaning the release binding ran:

| Case | `main` (42c8fee) | with the change below |
|---|---|---|
| Super+Return, Super let go | 1 (wrong) | 0 |
| Super + click, Super let go | 1 (wrong) | 0 |
| Super alone | 1 | 1 |

**A suggested change:** a binding that only acts on release (it has no action on press, so it is a tap) is called
off when another key or a mouse button is pressed while it is held. A key that has both, as hold-to-talk does
(press starts, `release` stops), is left as it is, so its release still always comes. The patch below is what
LatteOS runs on top of 0.6.9:
